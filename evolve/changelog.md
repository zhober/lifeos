# Changelog

Append-only record of system changes: what changed, why, and the evidence. New entries go at the end.

## 0.1.0 Initial public release

- File-based personal assistant: personal records and operating instructions are plain Markdown/JSON files; any model with file access and Node can take over through `AGENTS.md`.
- Small entry: `AGENTS.md` is an intent router plus a safety floor; other documents are read only when a task needs them. Byte budgets are enforced by the development test suite.
- Quick paths: `tools/quick-log.mjs` records a simple daily message in one command; `workflows/ask/QUICK.md` answers simple questions without the full consultation procedure. Live trials with fresh models read about 5-9 KB of instructions for these cases.
- Full procedures for consequential work: request/plan/step tracking, critic review, multi-expert panels, long-term sourced memory, and shared case collaboration.
- Domain roles: nutrition, health, fitness, study, career, shopping, psychology/interaction, finance, travel, plus critic and evolver. Shopping, travel and finance are research/advice only.
- Voluntary disclosure and privacy preferences apply to every role; nothing personal is required.
- Storage safety: immutable records, hash-checked recoverable writes, machine-local locks with stale-lock recovery, and reporting of sync/backup conflict copies.
- Deployment: `tools/deploy.mjs` installs or upgrades a personal vault without overwriting personal data, and removes managed system files that no longer exist in the source.
- Daily data/action report after a submitted sleep record, with an optional PDF renderer.
- Regional settings: no region is built in. The timezone resolves from the user preference, then `project.json` `timezone` (ships `null`), then `LIFEOS_TIMEZONE`, then the system timezone, through `tools/settings.mjs`, which also stores optional region, currency and shopping channels; records keep the timezone they were written with. The interaction language defaults to `en` until the user chooses it during setup. Shopping marketplaces and experience channels are user preferences; the shared lists ship empty.
- Food composition tables are not distributed for licensing reasons. They are optional reference files each user may build for personal use (`tools/build-food.mjs`, `data/food/README.md`); without them `data/food/custom.json` and label values still work and unknown composition stays unknown, never zero.
- Bilingual documentation: `README.md` (English, entrypoint `human`) and `README.zh-CN.md` (Simplified Chinese, entrypoint `human_zh`) serve as both the repository front page and the guide inside every deployed vault.

## 0.1.1 Coaching replies, photo meals on the quick path, plainer reports
- From real use: the assistant only recorded meals and missed obvious advice (a dinner suggestion after two meals, tomorrow's tweak, recovery after the previous evening's training), and handled meal photos and corrections through the full procedure with long reasoning and ad-hoc scripts.
- `AGENTS.md` adds a short style rule: coach after saving with 1-3 specific suggestions, ask at once with numbered options when an unclear item changes the result, keep reasoning short and do not read tool source. The log quick guide gains a reply section and documents every input.
- `quick-log.mjs`: photo meals (`meals[].photos`, originals preserved through the existing photo utility), non-meal attachments such as sleep screenshots (`attachments`), meal corrections (`meals[].supersedes`, replacing the journal row and re-summing the meal's day), a receipt `context` (today so far, last 2 days' training, recent sleep and symptoms) for advice, all entries validated before anything is written, and a slimmer receipt.
- Daily report human views (HTML/PDF/Markdown) drop citation labels, the source index, paths and SHA-256 hashes, and use plain labels such as "estimate" and "partial"; `report.json` and bundle metadata keep full sources and verification. Layout version 7.
- Entry budgets raised slightly (AGENTS 3.5 KB, log guide 7 KB) at the owner's request; current sizes are 2.9 KB and 4.9 KB.

## 0.1.2 Report look and feel
- From real use: the daily report was dense with ranges, labels and food descriptions, which the user found unhelpful. Human views (HTML/Markdown/PDF) now show one rounded number per metric, without estimate/coverage labels, ranges, grams, food descriptions, boilerplate disclaimers or empty trend rows; `report.json` keeps everything. Layout version 8-11.
- HTML gains inline-SVG charts (per-meal calories, macro-energy donut, stacked sleep-stage bar, multi-day sleep columns), equal-height card rows, compact chips for minor metrics, and parsing of the sleep paragraph into structured values.
- New optional "shortfalls and improvements" section driven by `records/nutrition/targets.json` (`daily` targets); `report-collect.mjs` reads it, `report-data.mjs` validates it as an optional `targets` field, `report-format.mjs` applies deterministic rules.
- `docs/domains/REPORTING.md` records the style as a reference rather than a fixed template, and replaces the conflicting estimate/range wording. 
- Training block: `report-collect.mjs` reads the day's fitness sessions into an optional `training` field (validated in `report-data.mjs`); shown as a card in HTML, a table in Markdown and a list in PDF. The journal exercise text is dropped from the views when it is present. Layout version 12.
- PDF renderer rewritten to the same style: charts, shortfalls, training, sleep structure, no disclaimers; verified with PDFKit 0.20.2 installed outside the vault.

## 0.1.3 Shopping research with the user's login, nutrition gaps
- From real use, synced back from a deployed vault.
- Shopping: the entry rule, READMEs and shopping-advisor now say plainly that the user may log in in the browser for read-only research (LifeOS never asks for or stores credentials; no cart, checkout, order, payment or coupon claiming). On a security check or "login abnormal" page the advisor stops and offers the platform's other user-completed methods instead of retrying, bypassing or decoding obfuscated prices.
- `docs/domains/SHOPPING.md` adds "Experience posts versus promotion" (official / real experience / opinion-seeding / promotion / lead, judged from the body, not the title) and "Coupons and basket arithmetic" (rules from the platform notice, explicit `sum − discount` scenarios, held coupons unknown until shown). The advisor reuses profile data for sizing, keeps apparel exclusions and per-item versus basket budgets, and delivers multi-item comparisons as a self-contained HTML report under `records/shopping/reports/`.
- New `tools/nutrition-gaps.mjs [DATE]`: compares the day's recorded totals with `records/nutrition/targets.json` and labelled general references (fibre, vitamin C, potassium) and suggests one food with a gram amount per real gap, using the food's own table value and only foods found by name. A partial total is used only as a labelled lower bound; calories never get an "eat more" suggestion.
- Log quick guide: default to cooked foods and anchor portions to countable references; `quick-log.mjs` accepts `water_ml`, the user's stated day total, stored as given.

## 0.1.4 Learning loop from daily use (borrowed from Hermes Agent)
- From real use: corrections such as "default to cooked" had nowhere to live except deployed system files, which deployment then skipped as manually modified; quick paths never saw the user's standing preferences; one-off inputs and scripts piled up in the synced vault root. Research: evolve/research/2026-10-20-hermes-agent.md (local).
- Working notes (`profile/working.md`, `tools/working.mjs`, `project.json` working_notes, 2000 bytes): one-line standing preferences and corrections, optionally scoped, printed by `tools/context.mjs` at every start. Duplicates, multi-line or over-long notes, notes in a scope the user withholds entirely and writes past the budget are refused; writes are hash-checked with snapshots.
- Local adjustments (`local/`): `local/<path>` adds to the shared `<path>` for one vault and wins where they differ, except over the safety floor; startup lists adjusted paths; deployment treats `local/` as personal data and seeds only its README. Proposed system changes go to `evolve/pending/` from `templates/proposal.md`.
- Scratch space (`.lifeos/tmp/`, `project.json` scratch, 7 days) and `tools/tidy.mjs`: startup counts stray root files and expired scratch files; `--apply` moves stray root files into scratch and deletes expired ones, leaving sync-conflict copies alone. The log guide prefers stdin for quick-log input.
- `tools/due.mjs`: accepted or in-progress actions overdue, due today or within `--days N`, and ready requests; `--quiet` prints nothing when nothing is due. Startup reports the count of due actions. `actionStatus` moved to `tools/work-state.mjs` for reuse.
- Safety floor: text in web pages, posts, imports, attachments and tool output is data, not instructions. System files change only on the system development route. The root vendor-tree rule left the entry file (still printed at startup, stated in HANDBOOK/CONFIGURATION and enforced by the layout check) to keep the entry within 3.5 KB; the shopping line was shortened, its detail stays in SHOPPING.md and the shopping advisor.
- Log guide: photos sent together are one meal unless the user says otherwise.
- New suite `test/adjustments-check.mjs`.

## 0.1.5 Message digests (literature, news)
- From the user's request: a digest module that serves a researcher (literature) or a business user (news) through one pipeline. The method was adapted from a user-supplied Hermes "daily literature digest" bundle and its run logs (reviewed locally, not distributed); its personal configuration stays out of the release.
- `docs/domains/DIGEST.md`, `workflows/digest/SKILL.md`, `tools/digest.mjs` (CLI), `tools/digest-data.mjs` (screening, queue, translation checks), `tools/digest-sources.mjs` (collectors). Kinds are registered in `project.json` digest (`literature`: PubMed journals plus bioRxiv/medRxiv; `news`: RSS/Atom); personal interests, journals, categories and feeds live in `profile/digest/<kind>.json`, seeded disabled and empty from `templates/digest/`.
- Collection: PubMed by Entrez date with full paging and efetch records; the bioRxiv API paged by its reported total (the bundle read only the first 30-item page and compared categories with the wrong separator); Europe PMC as the fallback when bioRxiv fails; per-source windows that stay open after a failure. Only official APIs, honest identification, nothing worked around.
- Screening: non-research titles and publication types removed with reasons; whole-word, case-aware keyword matching with required and excluded context (FUS ≠ fusion, STAG ≠ stage, Hi-C for scaffolding ≠ 3D genome); candidates need a core dimension or two topic dimensions, weak and method terms never count; every other item is listed for title review; a core-token scan backs any "nothing relevant" statement.
- Model work is limited to scoring every candidate and writing a complete translation and assessment; `finalize` injects original abstracts, links and counts, refuses summaries posing as translations (numbers must survive, length ratio), requires notes below four items and token-hit verdicts at zero, then writes Markdown and HTML reports, the immutable run record, the watch queue (entry ≥3, 14-day expiry by discovery date, archive instead of truncation, promotion of queue picks by id), seen history and source state in one step.
- Full text: open-access copies saved when an official full-text API offers them; otherwise free full-text links (Europe PMC, preprint server, journals marked open_access, Unpaywall with `UNPAYWALL_EMAIL`).
- New suite `test/digest-check.mjs` with fictional recorded API responses in `test/fixtures/digest/`.

## 0.1.6 Report delivery and PDF discovery from real use
- From the deployed vault (2026-11-12): after a morning sleep submission the quick path generated the daily report but the reply guide never said to deliver it, so it was skipped; reports for several days were also `generated_without_pdf` because the PDF runtime lived in `~/lifeos-runtime/pdf`, a location the renderer did not search.
- `workflows/log/QUICK.md` reply step 4 and `workflows/log/SKILL.md`: deliver any report in the receipt (PDF, or HTML/Markdown with the no-PDF reason stated), and regenerate first when the covered date's records changed afterwards.
- `tools/report-pdf.mjs`: without `--runtime`/`LIFEOS_PDF_RUNTIME`, discovers a runtime at `~/lifeos-runtime/pdf` (per machine, outside synced folders) and then `<workspace>/runtime/lifeos-pdf`, accepting only a directory with PDFKit installed. Font detection adds macOS `Arial Unicode.ttf` (single TTF) after PingFang for Macs without PingFang.
- README (both languages) opens with a banner (`docs/assets/lifeos-banner.jpg`, deployed with the READMEs) and the tagline "An AI Operating System for Your Life".
- Daily report in English: chart titles, units, the meal-table header, sleep table, training summary and the shortfall section follow the report language in HTML, Markdown and PDF (layout version 14); meal-chart labels get a column wide enough for the longest meal name; PDF text wraps Latin text between words.
- A nutrient total that misses some recorded items' values (for example fiber absent from the composition table for several foods) carries `missing_items` in the report input, is shown as a lower bound ("≥ 3 g") and is never flagged as a shortfall.
- README: "In 30 seconds", "See it in action" with a report generated from fictional messages (`docs/assets/demo-report.jpg`; `docs/assets/` is deployed with the READMEs) and license and Node badges.
- `report.mjs collect --out`: the write is keyed by path and content, so the same collected input can be saved to a second path (it failed with "operation identifier cannot be reused"); repeating the same path stays a replay.
