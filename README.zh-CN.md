# LifeOS

[English](README.md) | 简体中文

LifeOS 是一个由普通文件组成的个人助理。你的日常记录、档案、长期记忆和建议，连同助理遵循的指令，都放在一个归你所有的 Markdown / JSON 文件夹里。任何能读写文件、能运行 Node.js 的 AI 智能体都可以打开这个文件夹接手：Claude Code、Codex CLI、Gemini CLI、Cursor，或任何会读取 `AGENTS.md` 的工具。模型随时可以换，文件始终是同一套。没有服务器，不用注册账号，也没有数据库。

> **仓库还是个人库？** 本仓库是 LifeOS 的源代码。仓库里的 `journal/`、`profile/`、`records/`、`memory/` 等个人数据目录装的是开发用的虚构示例数据，请不要在这里记录自己的生活。你需要另外部署一个**个人库**（见“快速上手”）并在那里使用。如果你是在已部署的个人库里读到这份文件，这些目录就是你自己的，最初都是空的，可以直接跳到“[开始对话](#开始对话)”。

## 功能

- **日常记录**：饮食（文字或餐照）、运动、睡眠、症状、体重、心情、精力、学习和工作，写进按日期的日志和带版本的结构化记录。原话逐字保留；估算附带范围和假设；不知道的值保持未知，绝不当成 0。
- **快速路径**：简单记录和简单问题只读一份简短指南、调用一次脚本，不走完整流程，开销接近一次普通对话。
- **像教练，不只是记账**：保存之后给出 1–3 条具体建议（下一餐可以补什么、明天怎么微调、训练后怎么恢复）；遇到会明显影响结果的不清楚之处，会马上用编号选项问你。
- **专家角色**：营养师、健康顾问、健身教练、学习教练（规划、选资源、AI 教学）、职业与效率教练、心理与人际互动教练、购物顾问、财务顾问、旅行规划师。审查员核查重要方案；会诊让多位专家共同分析一个问题；“迭代师”负责新增或修改专家。
- **长期记忆**：跨年份保存带日期和来源的事实与事件，更正以关联新记录的方式保存而不是覆盖。请求可以暂停、继续、取消或改计划。
- **记住你的习惯**：你纠正过的默认做法（比如“默认按熟食估算”）会写成一条工作笔记，存在 `profile/working.md`，每次对话都会读到。你对流程的个人调整放在 `local/`，升级不会覆盖；值得推广的改动写成提案放进 `evolve/pending/`。
- **消息速递**：文献速递会采集你所选期刊的全部新论文和预印本，按你的研究方向筛选、评分，报告里附完整英文摘要、逐句翻译和研判；新闻速递从你订阅的 RSS 源采集。各类速递共用同一套流水线，可以继续添加新的类型。
- **日报**：按天汇总数据与行动，保存为 JSON、Markdown、HTML，PDF 可选。
- **隐私优先**：所有个人信息都是自愿提供的；你拒绝过的话题，换任何模型打开个人库都继续有效。
- **涉及钱和预订只给建议**：购物、旅行、财务只做调研和建议，LifeOS 不会下单、预订、付款或提交表单。购物调研时你可以自己在浏览器里登录，LifeOS 只看不动：不加购物车、不进结算、不下单付款、不领券，也不会索要或保存账号凭证。

## 运行要求

- **Node.js 20 或更新版本**。工具都是无依赖的 Node 脚本，无需安装任何包。
- **一个 AI 智能体**，能在文件夹里读写文件并执行命令。能否识别餐照、能否联网查资料，取决于你使用的模型和工具。
- **可选（PDF 日报）**：在个人库之外用 npm 安装的 PDF 运行库，以及一款可嵌入的中文（CJK）字体。

## 快速上手

```bash
git clone https://github.com/zhober/lifeos.git
cd lifeos
node tools/deploy.mjs ~/lifeos-vault           # 预览：列出将要创建的文件
node tools/deploy.mjs ~/lifeos-vault --apply   # 创建个人库
```

`deploy.mjs` 按脚本自身的位置找到源目录，在哪个目录运行都可以；相对的目标路径按当前目录解析。Windows PowerShell 中请写完整路径，例如 `$HOME\lifeos-vault`。个人库里会有指令、工具和空的个人数据目录，示例数据不会复制过去。个人库可以放在任意位置，包括同步文件夹。

## 开始对话

把个人库目录作为智能体的工作目录打开。

- **Claude Code**，在个人库目录中运行：

  ```bash
  claude --setting-sources user --settings config/runtimes/claude-code.json --append-system-prompt-file config/BOOTSTRAP.md
  ```

  `--settings` 适配文件可以省略：它只增加数据目录的编辑权限，以及启动时显示日期、时区和语言的钩子；只用 `claude --append-system-prompt-file config/BOOTSTRAP.md` 也能工作。
- **会自动读取 `AGENTS.md` 的智能体**（例如 Codex CLI）：在个人库目录中直接启动。
- **其他工具**：把 `config/BOOTSTRAP.md` 作为指令或系统提示词加载，或者第一句话说“读取 AGENTS.md 并照做”。

第一次使用时，助理会先问你想用哪种语言（选定前默认英文；如果你一开始就用中文，它会用中文问）。语言确认后才会继续填写档案，档案内容全部可以跳过。以后说“以后用英文”或“切回中文”即可更改；临时要求用另一种语言回答不会改掉设置。

## 怎么跟它说话

像平时聊天一样写就行，助理会按意图自动选择流程。

| 你说 | 会发生什么 |
|---|---|
| “中午一碗牛肉面，两百多克面，一个卤蛋。晚上跑步 30 分钟，膝盖有点疼。昨晚 1 点睡 7 点半起。” | 快速记录：原话存档，一步写好饮食、运动、症状、睡眠记录和当天日志；回复简短确认（附估算范围），再给 1–3 条建议 |
| *（发一张餐照，或睡眠截图）* | 同样走快速路径：保留原图，由支持图片的模型识别食物、估算份量，并写明假设 |
| “包子其实是猪肉馅的，豆浆是微甜的。” | 快速更正：这一餐生成新版本，旧版本保留，当天合计重新计算 |
| “我上周睡得怎么样？” | 根据你自己的记录快速回答，标明哪些是数据、估算或缺失，并附简单建议 |
| “问问健身教练，膝盖不好怎么练腿” | 单个专家咨询；重要方案可交给审查员核查 |
| “会诊：最近几周总是很累，该怎么调整？” | 多位专家分析，汇总成一份方案，再由审查员审核 |
| “复盘本周” / “生成昨天的日报” | 周复盘 / 日报 |
| “从向量开始教我线性代数” | 学习教练进入教学模式，下次可以接着上 |
| “先暂停” / “取消旅行那个请求” / “把目标改成……” | 请求暂停、取消或改计划，已完成的结果保留 |

改记录日期、撤回记录、导入文档，以及财务、购物、旅行、职业类记录，会自动走完整流程。流程名称（`/log`、`/ask`、`/panel`、`/review`、`/report`、`/learn`、`/import`、`/setup`、`/expert`）只有在你的工具注册了它们时才能当斜杠命令用；直接说话始终有效。`node tools/experts.mjs` 可列出全部专家。

### 餐照小贴士

拍清楚整盘食物就可以，不要求每餐称重；参照物、包装标签或剩菜照片能让估算更准。多角度照片归为同一餐；剩菜、共享菜或之后补充的份量会修订这一餐并保留旧版本。可以估算热量、蛋白质、脂肪、碳水、纤维、钠，以及资料支持的部分维生素和矿物质，信息不足的值留空。照片数量不代表一天记全了；当天结束时可以说“今天吃的都记完了”。模型读不了图片时，会先保留待分析的记录。

## 数据存在哪里

| 位置 | 内容 |
|---|---|
| `journal/YYYY/YYYY-MM-DD.md` | 每天一篇日志：数值在开头 frontmatter，下面是各分区，以及只追加的原话区 |
| `records/` | 带版本的结构化记录：餐食、每日营养、训练、健康、职业、购物、财务、多专家共享病例 |
| `inbox/<来源>/` | 你提供的原件（餐照、导出文件、文档），原样保存 |
| `advice/`、`reviews/`、`reports/daily/` | 专家建议、周/月复盘、日报 |
| `memory/`、`tasks/`、`actions/`、`history/` | 长期记忆、请求与步骤、行动与结果、写入前后快照 |
| `profile/`、`experts/`、`data/food/custom.json` | 档案、目标、`preferences.json`；各专家笔记；你自己的食物 |

更正会生成新版本，不会改写旧记录。可以用 Obsidian 等任意 Markdown 工具浏览个人库，装 Dataview / Tracker 插件还能画体重、睡眠曲线。

## 设置

在个人库根目录运行，或者直接让助理帮你改。

```text
node tools/language.mjs show | set zh-CN               交互语言（en、ja、de……）
node tools/settings.mjs show                           查看时区及来源、地区、货币、购物渠道
node tools/settings.mjs set timezone Asia/Shanghai     任意 IANA 时区；system 表示跟随系统
node tools/settings.mjs set region CN                  ISO 3166-1 两位代码；none 清除
node tools/settings.mjs set currency CNY               ISO 4217；none 清除
node tools/settings.mjs set marketplaces jd,taobao     常用购物平台；experience_channels 同理
node tools/privacy.mjs show health                     查看某个领域生效的隐私选择
```

不内置任何地区。时区依次取：你保存的偏好、`project.json`、环境变量 `LIFEOS_TIMEZONE`、系统时区。已有记录保留当时的时区，改设置不会改写历史。地区、货币和购物渠道只在任务需要时才问，可以跳过。

## 隐私

所有个人信息都是自愿的：健康、身体、家庭、关系、工作、位置和财务。可以只给区间、匿名描述，或者什么都不给。你拒绝的问题不会被再次追问、换个说法问、交给别的专家问，也不会从旧文件里推出来；长期的限制保存在 `profile/preferences.json`，换任何模型都继续生效。启动时只显示是否有日志，不展示内容。购物或旅行调研遇到需要登录的页面时，由你自己扫码或输入密码；账号凭证不会存进个人库。

这些规则是模型遵守的指令，不是加密或权限控制。请像保护其他私人文件一样保护个人库目录，也要知道模型读到的内容会经过你所用模型的服务商。

## 日报

可以要求生成任意日期的日报；也可以早上提交昨夜睡眠：睡眠记录保存并完成描述性分析后，自动生成前一天的日报，不看钟点，凌晨提交也算。睡眠按醒来的日期保存。某天除了这条睡眠没有任何其他记录时，不会生成空日报。缺失的数据保持缺失，不填 0；更正后生成新版本。

日报以数据和行动为主：首页最多四张重点卡片（默认优先饮食、睡眠和运动，没有记录的领域不占位），后面展开记录。没装 PDF 运行库也能用，会保存 JSON、Markdown、HTML 三份。需要 PDF 时，运行 `node tools/report-setup.mjs <个人库之外的目录>`（需要 npm 和网络），再用 `--runtime` 或环境变量 `LIFEOS_PDF_RUNTIME` 指定该目录，并准备一款可嵌入的中文字体，详见 `config/runtimes/pdf/README.md`。

## 食物成分数据

出于版权原因，LifeOS 不分发任何食物成分表。没有成分表也照常可用：`data/food/custom.json` 里你自己的食物和包装标签数值都能计算，其他食物的营养素保持未知。想供个人使用，可以从公开的整理数据生成《中国食物成分表（第 6 版）》：`node tools/build-food.mjs <数据目录> [gi.json]`。具体步骤，以及把其他你有权使用的成分表转换成 LifeOS 格式的方法，见 `data/food/README.md`。生成的表请勿再分发。

## 升级

更新你的仓库克隆，然后对已有个人库运行同样的命令：

```bash
git pull
node tools/deploy.mjs ~/lifeos-vault           # 预览
node tools/deploy.mjs ~/lifeos-vault --apply
```

个人数据永远不会被覆盖。你在个人库里改过的系统文件默认跳过并提示，加 `--force` 才覆盖。新版本删掉的系统文件，只有你没改过时才会删除；改过的保留并提示。语言、时区和隐私选择在升级后保持不变。

## 常见问题

- **提示 “Write is locked by ...”**：另一个写入正在进行，或之前被中断。稍后重试；`node tools/files.mjs locks` 查看锁，`node tools/files.mjs locks --clear-stale` 只清理能证明已失效的锁（本机持有进程已退出，或来自其他主机、无法读取且超过 24 小时的锁）。锁放在个人库之外的本机目录，同步工具不会复制它们。
- **同步冲突副本**：个人库放在同步文件夹、两台设备改了同一个文件时，同步工具可能留下副本。LifeOS 只报告、从不合并。`node tools/conflicts.mjs` 列出每个副本和对应的原文件；把要保留的内容写进原文件，再删除副本。个人数据里的副本只是警告；遮住系统文件的副本会让布局检查失败。
- **布局检查**：`node tools/check-layout.mjs` 检查个人库结构和设置，只报告，不删除也不修复。
- **日期不对**：先看 `node tools/settings.mjs show`。00:00–03:59 发的消息通常算作刚结束的那一天；睡眠按醒来的日期保存。
- **营养显示未知**：这种食物不在 `custom.json` 或已安装的成分表里；把它加进 `custom.json`，或提供标签数值。

## 已知限制

- 日志标题、表格列名和很多工具提示是中文的。日志格式是固定的存储结构，不会翻译；助理会用你选择的语言和你对话。
- 估算、建议和审查的质量取决于所用模型。脚本负责存储、计算和检查，判断由模型完成。
- 没有后台调度：你不跟智能体说话，什么都不会运行；提醒和日报都由对话触发。
- 记忆检索基于本地关键词、别名、实体和显式关系，不使用 embedding。
- PDF 日报需要可选运行库和中文字体。
